# Конформанс-набор провайдера

Чёрный ящик: натравливается на адрес ЛЮБОГО провайдера независимо от языка.

```bash
go run ./cmd/conformance -addr localhost:9200
```

Проверяет: хендшейк и совместимость мажора, обязательные поля `Descriptor`,
честность объявленных `capabilities`, заполненность `expires_at` и
`allowed_origins` в `Resolve`, поведение на неизвестном ID, детерминизм
пагинации, отсутствие протечки сырых структур площадки в канонические поля.

**Прохождение — условие приёма плагина.** Контракт должен быть исполняемым,
а не документацией: иначе провайдер на другом языке разъедется с ожиданиями
хоста через месяц, и обнаружится это в проде (ADR-0001).

## Сейчас

Площадки в процессе (на Go и скрипты, ADR-0017) проверяются тем же
контрактом в виде живого набора `internal/adapter/providers/providertest`:

```bash
go run ./cmd/sourcekit check <id|sources/файл.js> -q "запрос" -fetch
```

Его же запускают движок на телефоне (кнопка «Проверить» у площадки) и приём
присланной правки (`sourcekit import`). Чёрный ящик по gRPC для площадок на
других языках остаётся задачей: `cmd/conformance` — заглушка.
