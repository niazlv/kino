# Архитектура

## Поток данных при воспроизведении

```
браузер ──1── core ──2── crawler-host ──3── provider(kinopub) ──4── площадка
                │                                  │
                │◀─────────── Source ──────────────┘
                │
                5 выпуск PlaybackTicket -> Redis
                │
браузер ◀──6── /stream/{ticket_id}/master.m3u8
   │
   7 (байты)
   ▼
gateway ──8── читает тикет по ID ──▶ Redis
   │
   9 X-Accel-Redirect ──▶ nginx ──▶ CDN площадки
   │
   10 при 403/410: TicketService.Refresh(ticket_id) ──▶ core   (generic, без провайдеров)
```

1–4 — резолв. 5 — единственное место, где встречаются провайдерская специфика
и доставка. 6–9 — перенос байт, полностью generic. 10 — единственная связь
gateway с остальной системой. Субтитры отдельными файлами идут тем же путём —
`/stream/{ticket_id}/sub/{n}.vtt`, по номеру в тикете (ADR-0010).

Шаг 8 происходит **один раз за сессию**, не на каждый сегмент.

## Дерево зависимостей кода

```
cmd/core ──▶ bootstrap ──▶ transport/{httpuser,httpadmin,grpcservice}
                       ──▶ app/{auth,catalog,playback,matching,admin,telemetry}
                       ──▶ adapter/{postgres,redis,providerclient}
                                       │
                            app ──▶ domain ──▶ ∅

cmd/gateway ──▶ bootstrap ──▶ transport/mediahttp ──▶ adapter/upstream
                                    │
                          domain/playback (только схема тикета)
                          gen/kino/gateway/v1
        ✗ НЕ зависит от gen/kino/provider и adapter/providers  (ADR-0002)

cmd/crawler ──▶ adapter/providerclient  (реестр: in-process | gRPC)
            ──▶ gen/kino/provider/v1

cmd/{core,crawler,engine,sourcekit}/providers.go   (тег !noproviders)
            ──▶ providers/all ──▶ providers/*  (сами площадки — ADR-0018)
                                     │
                протокол: domain, app/provider, adapter/providers/{source,sitekit}
        ✗ internal/ и pkg/ НЕ импортируют providers/ — каталог уезжает в
          приватный репозиторий, ядро собирается без него
```

## Пять осей версионирования

| Ось | Контракт | Механизм | Заметка |
|---|---|---|---|
| 1 | хост ↔ плагин | `api_major`/`api_minor` в `Describe()` | capabilities — отдельно от версии, иначе мажоры инфлируют |
| 2 | каноническая модель | `schema_version` + сохранённый `raw` JSONB | из `raw` пересчитываем, не обходя площадку заново |
| 3 | `PlaybackTicket` | поле `v` | короткий TTL делает миграции бесплатными |
| 4 | фронт ↔ core | `/api/v1` + `min_client_version` | service worker в PWA кеширует старый бандл |
| 5 | схема БД | goose | координируется с осью 2 |

Инструмент для 1 и 3 — `buf breaking` в CI.

**Политика совместимости:** хост держит текущий мажор Provider API и
предыдущий; `core` и `gateway` версий N и N+1 обязаны сосуществовать.
Атомарно выкатить разнородные плагины в разных контейнерах невозможно, а
каждый несовместимый деплой gateway рвёт всем просмотр.

## Слои

См. [ADR-0006](adr/0006-code-layout.md) и [boundaries.md](boundaries.md).

Коротко: `domain` — правила без зависимостей; `app` — use cases и порты,
единственный слой, где живёт бизнес-логика и где её удобно тестировать;
`adapter` и `transport` — края; `bootstrap` — ручная сборка.

## Порядок работ

- **Фаза 0** — эксперимент с CDN-ссылками (ADR-0003). Блокирует `gateway`.
- **Фаза 1** — MVP: auth, инвайты, синк каталога, gateway, плеер, прогресс.
  Один провайдер in-process, реестр уже за контрактом.
- **Фаза 2** — канонические ID и матчинг, вынос кравлера, второй провайдер.
  Здесь контракт проходит проверку реальностью.
- **Фаза 3** — скачивание + ремукс, офлайн в PWA.
- **Фаза 4** — TV (Android TV / webOS): PWA туда не годится.

## Темп обхода площадки

Аккаунт на площадке один на всё: обход каталога и просмотр тратят один
лимит, и на перебор площадка отвечает 429 всем сразу. Отсюда правила:

- **По курсору каждые полчаса.** Площадка отдаёт изменения по убыванию
  времени, обход останавливается на первом элементе старее курсора —
  единицы запросов.
- **Целиком — ночью и не чаще раза в полнедели** (`CRAWLER_FULL_EVERY_H`,
  `CRAWLER_NIGHT_FROM/TO`, `CRAWLER_TZ`). Отметка последнего полного обхода
  лежит в `provider_sync_state.last_full_at`, а не в памяти: иначе каждый
  деплой начинал бы с полного прохода.
- **Целиком — не залпом.** Полный обход растягивается примерно на
  `CRAWLER_FULL_SPREAD_MIN` (150) паузой после каждого тайтла: раньше
  пятьдесят тысяч тайтлов пролетали за четверть часа, и площадка отвечала
  ограничением всем сразу.
- **`CRAWLER_FULL_RESYNC=true` — только для первого заполнения.** На боевом
  он простоял включённым и держал аккаунт в ограничении круглые сутки.
- **Живой поиск.** Если у нас по запросу пусто, ядро спрашивает площадку
  (один запрос), кладёт найденное в каталог и отдаёт уже с нашими id.
  Только при пустом результате — иначе каждая буква тратила бы лимит.
- **Просмотр переживает 429:** резолв серии повторяется дважды с короткой
  паузой, дальше — честный 503 с просьбой повторить.


## Несколько площадок

Подробно — [ADR-0008](adr/0008-multiple-sources.md). Коротко:

- **Один тайтл — много площадок.** Элемент площадки привязан к тайтлу
  (`external_refs`) и, если площадка заводит страницу на сезон, — к сезону.
  Склейку решает `app/matching`: внешние ID, номер MAL, однозначное
  совпадение названия с годом и видом. При сомнении — новый тайтл;
  дубли сливаются в админке («Тайтлы»), с переносом прогресса.
- **Серия у площадки — в её нумерации** (`episode_offers`). Пересчёт
  делается при записи серий, резолв спрашивает площадку её же номерами.
- **Какая площадка играет:** выбранная в плеере (запоминается для тайтла),
  иначе по приоритету (`PROVIDER_PRIORITY`, для тайтла — в админке); нет
  серии или площадка не отвечает — следующая.
- **Озвучка у аниме-площадок — отдельный поток**, а не дорожка в HLS:
  переключение выпускает новый тикет с того же места. Запоминается студия,
  а не номер.
- **Озвучки одним списком** ([ADR-0011](adr/0011-voices-across-sources.md)):
  площадка с `CapVoices` называет озвучки серии без выдачи потока, core
  сводит их по студии (`provider.VoiceKey`) в
  `GET /episodes/{id}/voices`. Плеер выбирает студию (`voice` в
  `/playback`), площадку под неё подбирает сервер; запомненная студия
  важнее запомненной площадки. Площадка вручную — «Источник» под «Видео».
- **Маршрут наружу у площадки свой** (`EGRESS_ROUTES`, `PROVIDER_EGRESS`):
  kinopub — через VPN, аниме-площадки — с российского адреса. Имя маршрута
  едет в тикете; шлюз знает маршруты, а не площадки.
- **Вырезание рекламы из потока** — правило в тикете
  (`DropOutsideOrigins`, `DropHosts`), применяет шлюз при переписывании
  плейлиста.
- **Досбор по номерам** ([ADR-0009](adr/0009-balancer-lookup.md)): площадка
  с `CapLookup` находит произведение по IMDb или Кинопоиску одним запросом,
  и при открытии любого тайтла такие площадки спрашиваются его номерами.
  Так «ЛордФильм» (балансер Alloha) даёт запасной поток и фильмам, которых
  на самом сайте нет.

```
                        ┌─ kinopub     ── маршрут default (VPN)
тайтл ── площадки ──────┼─ animego.me  ── маршрут direct ── CVH | AniBoom | Kodik | Sibnet
   │                    ├─ animego.fr  ── маршрут direct ── CVH | Kodik
   │                    └─ lordfilm    ── маршрут direct ── Alloha
   └─ серия ── episode_offers: (площадка, её сезон, её номер)
```
