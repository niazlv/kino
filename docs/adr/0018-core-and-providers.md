# ADR-0018. Ядро и площадки: граница для публикации

**Статус:** принято · **Дата:** 2026-11-23 · Развивает ADR-0001 и ADR-0017

## Контекст

Исходники собираемся публиковать. Ценность платформы — слой состояния
просмотра, плеер и приложения; их можно и нужно открыть. Адаптеры площадок —
разбор чужих сайтов и плееров, ключи балансеров, обходы защиты — открывать
не стоит: и по юридическим соображениям, и практически (площадки — расходники,
публичный разбор ломают быстрее). Отсюда решение: **публичное ядро + приватный
репозиторий площадок**. Архитектура плагинов (ADR-0001, ADR-0017) это
позволяет, но до этого решения граница существовала только в голове:

- адаптеры лежали в `internal/adapter/providers/*` вперемешку с реестром
  (`source`), хостом скриптов (`script`) и контракт-тестами (`providertest`);
- реестр сборки (`bootstrap/providers`) сам импортировал пакет со всеми
  площадками и kinopub с его хранителем входа — любой бинарник ядра тянул
  все адаптеры;
- хост скриптов — общий механизм — импортировал разбор чужих плееров
  (`jutsu`, `embeds`) и вшитые скрипты (`sources`);
- ядро знало kinopub по имени в пяти местах: состояние входа (`kpauth.Status`
  в `OnAuth`), источник истории для переноса, мост склейки по названиям,
  образец написания озвучек, вход по коду в движке (`kplogin.go`, поле
  `kinopub` в `/engine/status`).

## Решение

### 1. Площадки — один каталог `providers/`

Всё, что уйдёт в приватный репозиторий, лежит в корневом `providers/`:
адаптеры (`kinopub`, `animegome`, `animegofr`, `lordfilm`, `filmix`,
`anilibria`, `anidub`, `jutsu`), разбор чужих плееров (`embeds`), вшитые
площадки-скрипты (`sources/*.js`), сборка `all` и заметки по площадкам
(`docs/`). Перенос в другой репозиторий — перенос этого каталога и трёх-четырёх
файлов `cmd/*/providers.go` (п. 3).

### 2. Протокол плагинов — в ядре, явным списком

Что площадке можно знать о ядре — это и есть протокол для плагинов на Go:

| Пакет | Что даёт |
|---|---|
| `internal/domain/{kernel,provider,catalog,playback}` | доменные типы и ошибки |
| `internal/app/provider` | порты: `Provider`, `Lookup`, `Voices`, `Segments`, `Thumbnails`; `DeviceLogin`, `AuthStatus` |
| `internal/app/matching` | разбор названий (`SplitSeason`) |
| `internal/adapter/providers/source` | `Spec` и реестр площадок |
| `internal/adapter/providers/sitekit` | вежливый HTTP-клиент, разбор HTML, `Stream`, мост «площадка на чужих плеерах» (`Site`) |
| `internal/adapter/providers/providertest` | исполняемый контракт |
| `pkg/*` | библиотеки |

Сборке `providers/all` ещё можно подключать хост скриптов (`script.SetPlayers`,
`script.Bundle`). Всё прочее — нарушение, его ловит `make boundaries`.

Общая часть `embeds` (клиент с паузой по хосту и повтором на 429, `Text`,
`Attrs`, `OriginOf`, `Stream`, `Span`) переехала в `sitekit`; в `embeds`
остались прежние имена-псевдонимы, код площадок не менялся. Типы моста
`Site`/`SitePage`/`SitePlayers`/`SiteOptions` — тоже в `sitekit`, `jutsu`
пользуется ими через псевдонимы.

### 3. Одна точка встречи: `cmd/*/providers.go`

Бинарники `core`, `crawler`, `engine`, `sourcekit` подключают площадки одним
файлом каждый:

```go
//go:build !noproviders
package main
import _ "github.com/niazleushkin/kino/providers/all"
```

Ни один пакет ядра (`internal/`, `pkg/`) `providers/` не импортирует. С тегом
`noproviders` всё собирается и работает с пустым реестром — так выглядит
публичная сборка. Умолчания движка, завязанные на конкретные площадки
(`PROVIDERS=anilibria,kinopub`, `KINOPUB_CLIENT_ID=android`), переехали из
`cmd/engine/main.go` туда же, в `cmd/engine/providers.go`.

### 4. Роли площадок — поля `source.Spec`, а не имена

То, что ядро знало «по имени kinopub», площадка объявляет сама:

| Поле | Было | Где используется |
|---|---|---|
| `Default` | `PROVIDERS` по умолчанию = `kinopub` | `LoadConfig` |
| `History` | `registry.Get(kpprov.ProviderID)` | перенос истории (core, engine) |
| `TitleBridge` | `WithBridge(kpprov.ProviderID, …)` | мост по названиям в обходчике |
| `VoiceNames` | `s.Provider == "kinopub"` | `voicenames.WithPreferred` |
| `Login` | `kplogin.go` на `kpauth` | вход по коду в движке |

Поля с `json:"-"`: в `/engine/sources` они не уходят, форма ответа для
приложения прежняя.

Состояние входа — общий `appprov.AuthStatus` (событие `source.EventAuth`
в `Env.Report`) вместо `kpauth.Status`. Вход по коду — порт
`appprov.DeviceLogin`; конечный автомат входа (интервалы, slow_down, сбои
связи) остался в движке и стал общим для любой площадки со входом, а
устройство авторизации kino.pub — `providers/kinopub/login.go`. Ручки —
`/engine/<id>/login` (для kinopub путь прежний). В `/engine/status` вход
площадок лежит в `logins`, и для совместимости с приложением — ещё и ключом
с id площадки (`"kinopub": {…}`), как раньше.

### 5. Хост скриптов не знает плееров

Хост площадок-скриптов (`script`) — ядро: он исполняет площадку, написанную
кем угодно. Разбор Kodik/CVH/Alloha/Sibnet/AniBoom — часть площадок. Хост
объявляет порт `script.Players` (`NewSite`, `Sibnet`, `AniBoom`), реализацию
регистрирует `providers/all`. Без неё скрипты пути «свои потоки» работают как
прежде, а путь `players` и функции `players.*` отвечают `script.ErrNoPlayers`
(движок покажет причину в статусе, сервер не стартует со сломанной
площадкой — как с любой неверной настройкой). Вшитые скрипты подключаются
так же — `script.Bundle(sources.FS)` из `providers/all`; `script.BundleFS()`
читают сборка реестра и `/engine/sources`.

Справочник автора площадки-скрипта — протокол, поэтому он публичный:
`docs/script-sources.md` (был `sources/README.md`).

### 6. Публичный снимок: пример площадки и самостоятельная сборка

Снимок для публикации (`scripts/publish-public.sh`) не берёт `providers/` и
`cmd/*/providers.go`. Чтобы в нём было что посмотреть и было с чего писать
свою площадку, есть **пример** — `examples/demo`: четыре открытых фильма
Blender Foundation (CC BY, атрибуция — в его README) с публичных тестовых
HLS-потоков, весь протокол площадки и тест исполняемым контрактом. Бинарники
подключают его файлом `cmd/*/demo.go`, который едет и в снимок. Описание
примера — `Default` (в снимке, где других площадок нет, это каталог по
умолчанию) и `Hidden` (в полной сборке он выключен, пока задан `PROVIDERS`,
и не виден в списке площадок на телефоне). Пример видит из ядра только
протокол — как и площадки.

Снимок обязан собираться у человека без приватной части:

- uTLS-клиент маршрутов (`browserhttp`) переехал из `kinopub-downloader` в
  `pkg/browserhttp`; ядро без площадок утилиту не тянет вовсе;
- `scripts/check-public-snapshot.sh <каталог>` делает снимок самостоятельным
  (убирает из `go.mod` require и replace `kinopub-downloader` — их требуют
  только площадки — и делает `go mod tidy`) и прогоняет `go build`, `go vet`,
  `go test` и `make boundaries`. Падение — снимок не публикуется. Вызывает
  его `publish-public.sh` после `git archive`, до проверок на личное, — так
  проверяется и публикуется уже итоговый `go.mod`.

## Чем держится

`scripts/check-boundaries.sh` (`make boundaries`):

- ядро не тянет `providers/` даже транзитивно и в тестах:
  `go list -deps -test -tags noproviders ./cmd/... ./internal/... ./pkg/...`;
- бинарники собираются без площадок: `go build -tags noproviders ./cmd/...`;
- площадки и пример `examples/` импортируют из ядра только протокол (п. 2) —
  список разрешённых пакетов в скрипте;
- gateway по-прежнему не знает ни площадок, ни хоста (ADR-0002).

depguard (`core-knows-no-providers`) ловит прямой импорт ещё в редакторе.
Тест `providers/all` сверяет роли с прежним выбором (kinopub — по умолчанию,
история, мост, образец озвучек, вход по коду). Снимок целиком —
`scripts/check-public-snapshot.sh` (п. 6).

## Как отделять (когда решим)

1. Приватный репозиторий = `providers/` + `cmd/*/providers.go`. Модуль —
   вложенный путь `github.com/niazleushkin/kino/providers`: правило `internal/`
   в Go смотрит на путь импорта, поэтому вложенный модуль может импортировать
   протокол из `internal/` ядра. Сборка — `go.work` из двух модулей (или
   `replace`), бинарники с площадками собираются в приватном репозитории.
2. Публичный репозиторий — без `providers/` и файлов `cmd/*/providers.go`;
   тег `noproviders` там больше не нужен.
3. **Историю git не публиковать как есть**: в ней все адаптеры и их
   testdata (сохранённые страницы сайтов). Публичный репозиторий — с чистого
   снимка (или `git filter-repo --path providers --invert-paths` плюс
   проверка, что в истории не осталось и прежних путей
   `internal/adapter/providers/{kinopub,embeds,…}`).

## Что осталось до публикации (не закрыто этим решением)

- **Хоста плагинов по gRPC нет** (`internal/adapter/providerclient` пуст):
  площадки подключаются только в процесс. Публичная сборка без приватной
  части работает с примером (`examples/demo`) и площадками-скриптами пути
  «свои потоки». Если нужна публичная сборка с внешними плагинами — это
  отдельная работа по `api/proto/kino/provider/v1`.
- **Docker-сборка** (`deploy/Dockerfile`, `docker-compose.yml`) собирает из
  родительского каталога и копирует соседний `kinopub-downloader`: так
  устроена выкатка полной сборки. У человека со снимком `docker compose
  build` не пройдёт — нужен свой Dockerfile с контекстом самого репозитория
  (без соседа) или правка этого вместе с выкаткой. `check-public-snapshot.sh`
  об этом предупреждает. Там же: `-ldflags -X …/providers/lordfilm.defaultToken`
  в сборочных скриптах в снимке — пустая подстановка.
- **Имена kinopub в строках ядра** — не код площадок, но видны: заголовок
  «Перенос из kinopub» и код события аудита `user.import_kinopub` в админке
  (код лежит в базе), `KINOPUB_PROXY` как прокси маршрута по умолчанию
  (переменная в бою), подсказка `kinopub --from` (имя CLI утилиты) в
  `share.go`, мёртвое значение `CRAWLER_PROVIDERS=kinopub=inproc` в
  `platform/config`. Переименовывать — вместе с выкаткой и миграцией.
- **Приложения** (Android, iOS, витрина) — публичная часть, но экран входа в
  kinopub в настройках движка и подписи источников в интерфейсе называют
  площадки по именам.
- Комментарии ядра местами объясняют решения на примере kinopub — это
  история решений, не код площадок.
