# ADR-0016. Свой сервер: адрес не зашит в клиентах

**Статус:** принято · **Дата:** 2026-11-23

## Контекст

Приложения (Android телефон/ТВ, iOS) ходили на сервер, зашитый при сборке
(`BuildConfig.BASE_URL`, `ApiClient.baseURL`). Для семьи этого хватало, для
открытого исходника — нет: каждому, кто поднял свой сервер, пришлось бы
пересобирать приложение. Нужно: человек вводит адрес своего сервера и входит
или регистрируется там — тем же приложением.

## Решение

### Визитка сервера `GET /api/v1/server` (без входа)

```json
{"kind":"kino-platform","api":1,"name":"Кино друзей","registration":"open"}
```

- `kind` — признак «это kino platform»: введённый адрес любого сайта ответит
  200, и без признака приложение перезапустилось бы на чужой сайт.
- `name` — `SERVER_NAME`, как сервер называет себя на экране входа; пусто —
  клиент показывает адрес.
- `registration` — `REGISTRATION`: `invite` (по умолчанию — семейный сервер,
  как было), `open` (любой дошедший заводит аккаунт сам; принесённый код всё
  равно проверяется и гасится), `closed` (только админка). Незнакомое
  значение — ошибка запуска: опечатка не должна молча открыть сервер всем.
- `local` — движок на устройстве (ADR-0015), у него регистрация `closed`.

Только то, что и так видно на странице входа: ни версии сборки, ни площадок.
Сервер старше визитки отвечает 404 — клиенты узнают его по `/api/v1/health`
и считают регистрацию по приглашению.

### Клиенты: сервер выбирается, данные раздельны

- **Адрес.** Вшитый в сборку сервер — только стартовая точка (`-PkinoUrl=`
  пусто — сборка без сервера: первый запуск спрашивает адрес). Ввод
  нормализуется до origin: без схемы — https, путь/запрос/фрагмент
  отбрасываются (человек вставит ссылку на тайтл), порт по умолчанию
  опускается, кириллический домен — в punycode. Платформа живёт в корне
  домена: витрина и ссылки шлюза (`/stream/…`) строятся от корня, подпути
  не поддерживаются.
- **Проверка до переключения.** «Проверить» → визитка → имя и режим
  регистрации на экране; только потом «Подключиться».
- **Данные по серверам.** У серверов разные id серий и тайтлов, поэтому всё,
  что на них ссылается (сессия, настройки входа, очередь отметок, опись
  скачанного, очередь загрузок, кэши карточек), живёт в профиле сервера.
  Вшитый сервер держит прежнее хранилище — обновление ничего не теряет;
  выбранный — `s_<12 hex sha-256 origin>`; движок — `local`. Вернувшись на
  прежний сервер, человек застаёт свой вход и свои недокачанные серии.
- **Смена — перезапуск.** Как и смена режима (ADR-0015): клиент API,
  хранилища и очередь загрузок строятся под один сервер на жизнь процесса.
- **Обновления приложения — с вшитого сервера**, а не с выбранного: APK
  подписан ключом того, кто собрал сборку, чужой сервер раздаёт APK со своим
  ключом, и Android его поверх не поставит.
- **http — только к серверу домашней сети**, сервер в интернете — только
  https (сертификат бесплатно выдаёт тот же Caddy). Домашний — по записи
  адреса, без DNS: IPv4 10/8, 172.16/12, 192.168/16, 127/8, 169.254/16,
  100.64/10 (CGNAT, Tailscale); IPv6 ::1, fc00::/7, fe80::/10; имя без точки;
  зоны .local, .lan, .home, .home.arpa, .internal, .localhost. http к
  остальным отклоняется на выборе сервера, без запроса в сеть; переадресация
  https → http в интернет — тоже. Адрес без схемы — сначала https, для
  домашнего хоста при сетевой ошибке — http. На http экран выбора
  предупреждает, что пароль и история видны в сети.
  - Android: `network_security_config` пускает http на уровне сети (диапазоны
    адресов он не умеет) — правило держит приложение (`ServerAddress.allowsCleartext`).
  - iOS: `NSAllowsLocalNetworking` — стандартное исключение ATS для локальной
    сети, обоснования в App Store не требует; публичные домены по http режет
    сама система. Она же уже нашего списка: пропускает частные IP (10/8,
    172.16/12, 192.168/16, 127/8, 169.254/16, IPv6 локальной сети), имя без
    точки и .local, но режет 100.64/10 (Tailscale) и зоны .lan, .home,
    .home.arpa, .internal — для них на iOS нужен https (проверено на
    симуляторе iOS 26.5); экран объясняет, что указать вместо.

## Отвергнуто

- **Один профиль с очисткой при смене сервера** — терялись бы вход и
  недокачанное при каждом переключении туда-обратно.
- **Обновления с выбранного сервера** — чужой ключ подписи, установка не
  встанет; «сервер обновлений» отдельной настройкой — лишняя сущность.
- **Подпуть (`https://host/kino`)** — витрина и шлюз строят адреса от корня.
- **Открытая регистрация по умолчанию** — семейный сервер не должен
  открыться всем после обновления.
- **http куда угодно (`NSAllowsArbitraryLoads`, открытый cleartext без
  правила)** — пароль по чужим сетям открытым текстом и обоснование для
  App Store; домашнему серверу хватает исключения для локальной сети.
- **Ограничение частоты открытой регистрации в core** — открытая регистрация
  лишь опция владельца сервера; защищать её (лимиты на прокси, капча) —
  его забота.
