# ADR-0008. Несколько площадок у одного тайтла

**Статус:** принято · **Дата:** 2026-09-16

## Контекст

К kinopub добавлены две аниме-площадки: animego.me (оригинальный AnimeGO)
и animego.fr (клон на DataLife Engine). Домены похожи, каталоги разные.
У обеих есть то, чего нет у kinopub (аниме без русского релиза, свежие
серии онгоингов, озвучки студий), и много того, что у kinopub есть.

Задача не «ещё один каталог рядом», а **дополнение**: одно произведение —
один тайтл, одна история просмотров, а площадки за ним подменяют друг друга.

Что показала разведка (2026-09-16, сохранено в тестовых данных провайдеров):

| | animego.me | animego.fr |
|---|---|---|
| Тайтлов | ~3,3 тыс. | ~5,6 тыс. |
| API | JSON плеера (`/player/{id}`), JSON-LD на странице | нет, только HTML |
| Изменения | карта сайта с `lastmod`, раз в сутки | «Последние обновлённые» и `/ongoing/` |
| Внешние ID | номер MAL в адресе плеера CVH | номер MAL у плеера CVH |
| Сезон | отдельная страница | отдельная страница «N сезон» |
| Плееры | CVH, AniBoom, Kodik, Sibnet | CVH, Kodik |
| Озвучка | отдельный поток на студию | отдельный поток на студию |

Плееры, через которые идут байты:

| Плеер | Поток | Заголовки | Срок | Привязка |
|---|---|---|---|---|
| CDNVideoHub | HLS/MP4 на okcdn.ru, до 1080p | UA того же семейства (иначе 400) | 24 ч | адрес и браузер резолва |
| AniBoom | HLS fMP4, отдельное аудио, до 1080p | Referer aniboom.one | нет | нет |
| Kodik | HLS на solodcdn.com, до 720p | нет | ~12 ч | iframe — **только российский адрес** |
| Sibnet | MP4 одним файлом | нет | ~8 ч | нет |

Рекламы внутри самих потоков не нашлось ни у одного плеера: она в их
веб-интерфейсах (VAST), которые платформа не использует.

## Решение

### 1. Склейка — `app/matching`, чистая логика

Порядок по надёжности: известная привязка → imdb → kinopoisk → номер MAL
(сезонный, переносит и сезон) → названия. По названиям — только
однозначно: тот же вид, аниме только с аниме, год ±1 (для сезона N>1 —
не раньше года первого), у кандидата нет этого же сезона с этой же
площадки. Сомнение — **новый тайтл**, а не склейка: дубль чинится слиянием
в админке без потерь, ложная склейка портит историю.

Ключи названий (`title_names`) строит Go, а не SQL: одна нормализация на
запись и поиск. У старых тайтлов их достраивает обходчик при старте.

**Сезоны (дополнение 2026-09-22).** animego.me пишет сезон голым числом
(«Гинтама 3»), и каждый такой сезон заводился отдельным тайтлом, а за
ним — цепочкой — и следующие: однофамильцы-сезоны делали неоднозначной
склейку по названию. На бою так было ~120 карточек-сезонов, а в 23 тайтлах
одна работа (один MAL) двух площадок стояла на разных сезонах — серии
второго сезона играли в первом. Правила:

- голое число — сезон, только если сериал его продолжает: у него уже есть
  сезон N−1 (для второго — первый или весь тайтл). «Макросс 7», «Кайдзю
  № 8», «Часть 2» сезоном не становятся;
- из однофамильцев для сезона N>1 хозяин — продолжающий этот номер, из
  заведённых целиком (kinopub) — ближайший по году (ремейки), иначе самый
  ранний; если сезон у лучшего занят другой работой — новый тайтл, а не
  кандидат похуже;
- обходчик лечит уже заведённое (`Reconciler.FixSeasons`, до слияния
  дублей): выравнивает сезоны одной работы по MAL (`matching.Realign`, верх
  берёт явный номер, закреплённое человеком не трогается) и переносит
  тайтл-сезон к сериалу вместе с сериями и прогрессом (`matching.Adopt`,
  `AdoptSeason`). `ShouldMerge` пару с одной работой на разных сезонах не
  сливает — иначе прогресс лёг бы в чужой сезон. `CRAWLER_FIX_SEASONS=dry`
  — только журнал решений, `off` — выключено.

### 2. Серия у площадки — в её нумерации (`episode_offers`)

Элемент площадки может покрывать один сезон (`external_refs.season_no`).
Номер пересчитывается **при записи** серий, пара «каноническая серия —
номер у площадки» хранится. Резолв спрашивает площадку её же номерами.
Здесь же видно, у кого серии нет.

### 3. Выбор площадки при воспроизведении

Порядок: выбранная человеком (в плеере, запоминается `source_pref`) →
приоритет. Приоритет площадки — из конфига при чтении
(`PROVIDER_PRIORITY`), для отдельного тайтла — вручную в админке.
Нет серии или площадка не отвечает — следующая. Выбор, сделанный руками
только что (`strict`), не подменяется.

«Не отвечает» ограничено сроком (дополнение 2026-09-26). До этого срока не
было: kinopub за мёртвым узлом VPN держал плеер две минуты — до таймаута
HTTP-клиента, — и только потом играл запасной AnimeGO. Теперь:

- площадке, за которой есть запасные, — 8 с, последней — 15 с, всему
  выбору — 25 с (живая отвечает за 0,3–2 с, замер на бою);
- отказы площадок переведены на язык домена: `kernel.ErrUnreachable`
  (сеть, прокси, TLS, таймаут, 5xx API — частный случай `ErrUnavailable`)
  говорит о площадке целиком, в отличие от «этой серии нет»;
- такая площадка запоминается лежащей на 3 мин (`app/health`, память в
  процессе core): выпуск тикета ставит её в конец очереди, страница тайтла
  не ждёт её серий. Не выбрасывается — у тайтла других может не быть. Пока
  играет запасная, её перепроверяют в фоне той же серией не чаще раза в
  20 с; ответ возвращает её в строй сразу;
- в ответе плеера `passed` — кого обошли и почему, витрина пишет
  «kinopub не отвечает — играет AnimeGO»: иначе смена озвучки выглядит
  поломкой;
- если не отдал никто, наружу идёт самая содержательная ошибка:
  недоступность важнее «не найдено».

Метаданные тайтла принадлежат площадке с наибольшим приоритетом;
остальные только заполняют пустое.

### 4. Озвучка как вариант потока

`Source.Variants`/`Variant`, `ResolveRequest.Variant`/`VariantLabel`.
Номер варианта понятен только выдавшей площадке, подпись студии —
любой: запомненная «AniLibria» подбирается на следующей серии и на другой
площадке. Обновление протухшего тикета берёт площадку и вариант из самого
тикета (`Ticket.Choice`, шлюзу непрозрачно).

### 5. Маршрут наружу — имя в тикете

`EGRESS_ROUTES` задаёт именованные выходы (VPN, прокси, напрямую),
`PROVIDER_EGRESS` — какой площадке какой. Реестр пишет имя маршрута в
`Source.Egress`, тикет несёт его в шлюз. Незнакомый маршрут — отказ, а не
тихий выход напрямую.

Критерий ADR-0002 держится: шлюз знает **маршруты**, а не площадки.
Новая площадка на известном маршруте не трогает конфиг шлюза; новый
маршрут — это инфраструктура, и её рестарт честный.

### 6. Реклама в потоке — правило в тикете

`DropOutsideOrigins` и `DropHosts`: сегмент вырезается из плейлиста вместе
со своими тегами (`pkg/m3u8.ErrDrop`), а не валит его. Сейчас вырезать
нечего, но у аниме-плееров вклейка с чужого домена — известный приём, и
правило ставит провайдер, а не конфиг шлюза.

### 7. Разбор плееров — `adapter/providers/embeds`

Общий для площадок: одни и те же плееры встраивают разные сайты, и
поломка при смене плеера должна чиниться в одном месте. Kodik прячет путь
запроса ссылок в JS (`atob`), ссылки кодирует сдвигом букв — оба читаются
заново, а не прибиты.

## Отвергнуто

- **Отдельный тайтл на площадку с переключателем «откуда»** — история
  просмотров раскалывается, ради чего проект и затевался.
- **Склейка по названию без года и вида** — «Монстр» 2004 года
  склеился бы с игровым кино.
- **Каноническая нумерация через абсолютный номер серии** — ни одна из
  трёх площадок его не отдаёт; сезон на элемент площадки решает все
  встреченные случаи, остальное чинит админка.
- **Выбор маршрута по хосту в конфиге шлюза** — это список площадок в
  шлюзе под другим именем.
- **Использовать их веб-плееры в iframe** — реклама, свой интерфейс на
  каждой площадке, ни прогресса, ни пульта.

## Следствия

- Боевому серверу нужен российский выход для аниме-площадок (Kodik)
  рядом с VPN для kinopub: `EGRESS_ROUTES=vpn=…,direct=`,
  `PROVIDER_EGRESS=kinopub=vpn,animego_me=direct,animego_fr=direct`.
- Первый проход новой площадки — полный (курсора ещё нет): ~3–6 тыс.
  страниц с паузой 0,4 с.
- Площадки без API ломаются от вёрстки. Разбор проверяется тестами на
  сохранённых ответах, живые тесты — `KINO_LIVE=1`.
