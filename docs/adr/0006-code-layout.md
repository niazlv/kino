# ADR-0006. Слои первого уровня, модули второго

**Статус:** принято · **Дата:** 2026-09-04

## Решение
`internal/` разложен **по слоям**, внутри слоя — по модулям:

    internal/domain/<модуль>     сущности и правила. Ноль зависимостей.
    internal/app/<модуль>        use cases + порты. Знает domain, не знает реализаций.
    internal/adapter/<техн>      реализации портов: postgres, redis, providerclient
    internal/transport/<вход>    httpuser, httpadmin, grpcservice, mediahttp
    internal/platform/           конфиг, логгер, пул соединений
    internal/bootstrap/          композиционный корень (DI)
    pkg/                         публикуемые библиотеки, ноль знания о домене

## Почему слои первым уровнем, а не фичи
Правило зависимостей становится видимым в дереве и **выразимым в линтере**.
`.golangci.yml` (depguard) запрещает `domain -> app/adapter/transport`,
`app -> adapter/transport`, `pkg -> internal`. Нарушение не проходит CI, а не
ловится на ревью по внимательности. При feature-first то же правило
пришлось бы описывать перечислением, и оно бы разъехалось.

Модуль вторым уровнем не даёт слою стать свалкой: `internal/app/catalog/`,
а не `internal/app/catalog_service.go` рядом с сорока другими файлами.

## Порты — там, где потребляются
Интерфейсы объявлены в `app/<модуль>/ports.go`, а не в отдельном `port/`.
Это Go-идиома «accept interfaces, return structs»; отдельный пакет
интерфейсов превратился бы в свалку без владельца.

## DI — ручная сборка в bootstrap
Конструкторы принимают интерфейсы; композиционный корень — `internal/bootstrap`,
`main.go` остаётся тонким. Wire/fx отвергнуты: на этом размере они добавляют
кодогенерацию или рантайм-магию без выигрыша, а компилятор и так проверяет
ручную сборку. Главное — **бизнес-логика не знает про контейнер**, поэтому
сервис поднимается фейками на 30 строк (см. `app/playback/service_test.go`).

## Границы `pkg/`
`pkg/` — не вторая свалка. Правило: **ноль знания о домене, публикуется
в отдельный репозиторий как есть**. Проверяется depguard'ом.

## Плеер
`web/packages/player` — отделяемый npm-пакет: без зависимостей `@kino/*`,
без знания об API и авторизации, со своим демо-стендом без бэкенда.
Точка склейки с платформой ровно одна — `apps/web/src/PlayerScreen.tsx`.
