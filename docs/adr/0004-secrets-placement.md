# ADR-0004. Секреты живут у своего провайдера

**Статус:** принято · **Дата:** 2026-09-04

## Решение
Креды площадки монтируются **в контейнер её собственного провайдера** (docker
secrets). Ни `core`, ни `gateway`, ни `crawler-host` их не содержат.
`PluginHost.GetSecret` — только для in-process провайдеров без своего контейнера.

## Следствие для масштаба
Добавление 15-го провайдера = одна запись в secret-бэкенде + монтирование
в один новый контейнер. **Ни один общий конфиг не растёт.** Разрастания
«конфига с 15 секциями секретов» не возникает нигде.

## Оговорка закрыта измерением

Фаза 0 показала: подписанные ссылки kinopub открываются **без единого
заголовка** (голый GET -> 200). Значит `Upstream.Headers` для этого провайдера
пуст, и gateway не видит секретного материала вообще. Пункты ниже остаются
в силе для будущих площадок, которые могут вести себя иначе.

## Известная оговорка (для провайдеров, требующих заголовки)
`Upstream.Headers` в тикете **могут** содержать токен, если CDN авторизует по
заголовку. Gateway его не хранит, но материал проходит транзитом через память.
Меры по убыванию полезности:

1. Проверить экспериментально (ADR-0003, п. «г»), нужен ли заголовок вообще:
   подписанные CDN-ссылки обычно несут подпись в query, и тогда в headers
   остаются `User-Agent`/`Referer` — не секреты, и дыра закрывается сама.
2. Поле помечено sensitive; **редакция реализована в логгере gateway**,
   а не держится на дисциплине разработчика.
3. Радиус поражения — токен общего технического аккаунта, доступ к которому
   и так есть у всей семьи. Не оправдание, но разница между «ротируем»
   и «инцидент».
