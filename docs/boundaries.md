# Границы

Инварианты, которые дороже всего восстанавливать задним числом. Каждый
проверяется автоматически — `make lint` (depguard) и `make boundaries`.

## Правило зависимостей

    transport ──┐
    adapter  ───┼──▶ app ──▶ domain ──▶ (ничего)
    bootstrap ──┘

Стрелки внутрь. `domain` не знает никого, `app` знает только `domain` и свои
порты. Реализации портов подставляются в `bootstrap`.

| # | Инвариант | Чем держится | Почему дорого потерять |
|---|---|---|---|
| 1 | `domain` не тянет `pgx`, `net/http`, `app`, `adapter`, `transport` | depguard | без этого правила бизнес-правила невозможно протестировать без БД |
| 2 | `app` не импортирует `adapter`/`transport` | depguard | use case перестаёт быть переносимым и подменяемым в тесте |
| 3 | `pkg/` не импортирует `internal/` | depguard | `pkg/` перестаёт быть библиотекой и становится второй свалкой |
| 4 | `cmd/gateway` транзитивно не знает провайдеров | depguard + `go list -deps` | добавление площадки потребует передеплоя gateway — а его рестарт рвёт просмотры (ADR-0002) |
| 5 | `@kino/player` не зависит ни на один `@kino/*` | `check-boundaries.sh` | плеер перестаёт публиковаться и разрабатываться отдельно |
| 6 | В `packages/player/src` нет импортов приложения | grep в `check-boundaries.sh` | то же, но протекает через исходники, минуя package.json |
| 7 | Ядро (`internal/`, `pkg/`) не знает площадок: `providers/` подключают только `cmd/*/providers.go`, с `-tags noproviders` всё собирается | depguard + `go list -deps -test` + `go build -tags noproviders` | площадки уезжают в приватный репозиторий, ядро публикуется (ADR-0018) |
| 8 | Площадки и пример `examples/` видят из ядра только протокол: `domain/*`, `app/provider`, `app/matching`, `adapter/providers/{source,sitekit,providertest}`, `pkg/` | список в `check-boundaries.sh` | иначе приватный репозиторий держится за внутренности ядра и ломается от любой правки в нём |
| 9 | Публичный снимок (без `providers/`) собирается и проходит тесты у человека без приватной части и без `kinopub-downloader` рядом | `scripts/check-public-snapshot.sh` в `publish-public.sh` | опубликованный код, который не собирается, хуже неопубликованного |

## Три пространства

| Пространство | Транспорт | Аутентификация | Поверхность |
|---|---|---|---|
| `user` | `:8080`, публичный | cookie-сессия | каталог, воспроизведение, свой прогресс |
| `admin` | `:8081`, наружу через Caddy как `/admin` | passkey (WebAuthn, оба фактора сразу) или пароль → частичная сессия → TOTP/passkey повышает её с ротацией токена; sudo-режим для опасных действий; лимит попыток | служебные операции, агрегаты |
| `service` | gRPC `:9090` | машинные креды | `TicketService` для gateway |

Сессия одного пространства недействительна в другом (`account.Session.Valid`).
Служебные креды не дают ни пользовательского API, ни админки.

**Аутентификация — в transport, авторизация ресурса — в app.** Middleware
собирает `auth.Actor`; решение «может ли этот actor трогать эту строку»
принимает `auth.Policy`. Сложить всё в middleware — частая ошибка: «может ли
Петя видеть прогресс Маши» становится непроверяемым в юнит-тесте.

## Что делать при протечке
Не добавлять исключение в линтер. Протечка означает, что контракт недостаточно
выразителен — расширять надо контракт (например, поле в тикете), а не
разрешать зависимость. Крайний случай для доставки описан в ADR-0002:
источник, не укладывающийся в generic-перенос, уходит в `DELIVERY_MODE_LOCAL`.
