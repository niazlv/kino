# Android-оболочка

`web/apps/android` — приложение для Android поверх витрины. Внутри системный
WebView, который открывает витрину с вашего сервера (KINO_URL при сборке). Своего интерфейса у него
нет, и это главное решение: витрина одна, обновляется обычным деплоем, а APK
пересобирается только при правке самой оболочки.

Почему не React Native: он не исполняет React-DOM, там другие примитивы и нет
CSS, так что «тот же фронтенд» означал бы вторую платформу с собственной
вёрсткой. Capacitor с `server.url` даёт нативное приложение с одним кодом
витрины.

## Что делает оболочка

Всё в `android/app/src/main/java/ru/sorewa/kino/MainActivity.java`:

- полноэкранное видео: клиент Capacitor принимает запрос и тут же гасит его,
  поэтому view плеера кладётся поверх окна, панели прячутся, экран
  поворачивается в альбом;
- «назад»: сначала выход из полного экрана, потом история WebView, с первой
  страницы — приложение в фон (ядро Capacitor 8 клавишу не трогает, а
  системное поведение закрывало бы приложение с любой страницы);
- отступы под строку состояния, навигацию и клавиатуру: с Android 15 окно
  рисуется под ними, витрина про панели телефона не знает;
- скачивание через системный загрузчик, имя файла из `filename*`.

`www/error.html` — единственная локальная страница: показывается, когда сервер
недоступен. Работает благодаря `Cache-Control: no-cache` на `index.html`
в Caddy; иначе WebView показал бы витрину из кеша с мёртвым API.

## Сборка

Нужны JDK 21 и Android SDK с платформой 36. Ключ подписи лежит в `keystore/`
(там же README), в git не попадает. Без ключа релиз соберётся неподписанным.

```bash
cd web && pnpm install
cd apps/android
pnpm apk                                        # релиз, боевой адрес
KINO_URL=http://10.0.2.2:5173 pnpm apk:debug    # отладка против стенда из эмулятора
```

Результат: `~/Library/Caches/kino-android/app/outputs/apk/release/app-release.apk`.
Иконки и заставка — `python3 docs/design/icon/gen.py --android`.

`~/Documents` синхронизируется iCloud: пока `cap sync` переписывает
`res/xml/config.xml`, рядом появляются копии «config 2.xml», которые валят
сборку. Задача `dropStrayResources` в `app/build.gradle` убирает их перед ней.

## Обновления

Интерфейс обновляется деплоем витрины, APK пересобирать не нужно.

Оболочка обновляет себя сама (`Updater.java`): при холодном старте и не чаще
раза в шесть часов читает `https://<домен>/app/version.json`; если
`versionCode` там больше установленного, предлагает обновиться, скачивает
`/app/kino.apk` в кеш, сверяет sha256 и отдаёт системному установщику.
Подпись проверяет сам Android, поэтому ключ в `keystore/` терять нельзя.
На Android 8+ при первом обновлении система один раз попросит разрешить kino
ставить приложения. «Позже» откладывает ту же версию на сутки.

Выложить новую версию:

```bash
# поднять versionCode и versionName в android/app/build.gradle, затем
./deploy/prod/publish-apk.sh          # соберёт релиз и выложит на сервер
./deploy/prod/publish-apk.sh --no-build
```

Файлы лежат на сервере в `/opt/kino/apk` (вне репозитория, том Caddy
`/srv/apk`), маршрут `/app/*` в Caddyfile. Первая установка — по ссылке
https://<домен>/app/kino.apk. На стенде тот же путь смотрит в
`deploy/apk/` (в .gitignore): положить туда APK и `version.json`, чтобы
проверить обновление против стенда.

## Ограничения и что проверено

- Capacitor помечает `server.url` как «не для продакшена»: мост в чужую
  страницу. Страница здесь своя, плагинов кроме встроенных нет.
- Проверено в эмуляторе Android 16 (Pixel 7) против локального стенда: вход,
  каталог, страница тайтла, HLS через hls.js, полный экран и выход из него,
  «назад», страница «Нет связи», самообновление с 0.1.0 на 0.1.1 целиком. Скачивание доходит до системного загрузчика
  и видно в «Загрузках»; сам перенос файла эмулятор не запускал.
- При первом полном экране Android показывает подсказку «Viewing full
  screen»; пока не нажать «Got it», клавиша «назад» уходит в неё. Одноразово.
- Android TV не адаптирован: оболочка подойдёт та же, но витрина не умеет
  пульт (оценка — в памяти проекта).

## Встроенная качалка

«Скачать» на странице серии внутри приложения не ведёт на прямой файл, а
отдаёт серию утилите kinopub, встроенной в APK: все озвучки и субтитры,
докачка, уведомления.

- Выбор дорожек — обычная шторка витрины (`DownloadDialog.tsx`), а не
  системное окно Android: она открывается сразу, ничего не выясняя заранее.
  Имена дорожек берутся из плеера (`Player.onTracks`) — ровно те, которые
  потом ищет утилита; в тикете названия другие. На узком экране шторка
  приезжает снизу.
- Мост `window.kinoApp` (`KinoBridge`) принимает задание, выбор папки и
  версию. Свою кнопку страница показывает только внутри приложения, в
  браузере остаётся обычная ссылка на файл. Перехват
  `/api/v1/episodes/<id>/download` в `KinoWebViewClient` оставлен запасным
  ходом.
- `DownloadService` (сервис переднего плана) запускает утилиту с
  `--progress-json` и читает JSON-строки. В уведомлении своя иконка, нажатие
  открывает страницу тайтла, рядом «Пауза» и «Отменить», на паузе —
  «Продолжить»; пока идёт загрузка, смахнуть его нельзя. «Отменить» стирает
  недокачанное, пауза — нет. Причина неудачи показывается словами утилиты.
  Готовые файлы переносятся в выбранную папку (SAF, право запоминается) или
  в `Фильмы/kino/<название>/` через MediaStore; итоговое уведомление
  открывает файл.

  Две ловушки, на которых уже обожглись: пауза и отмена глушат утилиту через
  `destroy()`, и чтение из оборванного потока падает исключением — его нельзя
  принимать за ошибку загрузки; а прежде чем трогать файлы, надо дождаться
  реальной смерти процесса, иначе «Отменить» стирает папку под живым
  процессом.
- Бинарники лежат в `jniLibs/arm64-v8a` как `libkinopub.so` (утилита,
  `GOOS=android`) и `libffmpeg.so` (минимальный ffmpeg n7.1 из официальных
  исходников, только сшивка `-c copy`; декодеры aac/h264/hevc обязательны,
  без них ffmpeg не пишет заголовок MKV). Собирает их
  `tools/build-bins.sh` (Go и NDK r27); в git они не хранятся. Для
  запуска исполняемых файлов из APK в gradle включено
  `jniLibs.useLegacyPackaging` и в манифесте `extractNativeLibs`.
- Утилите достаточно cookie сессии витрины: отдельного входа нет.

Проверено на эмуляторе против стенда: «Масяня» s1e2 (минута) — выбор,
загрузка, MKV в `Movies/kino/Масяня/`, уведомление «Готово». И фильм
`#/title/53014` целиком (fMP4/h265, два часа): пауза, продолжение, нажатие
на уведомление, в готовом MKV ровно выбранные дорожки.

Эмулятору нужен запас на диске: утилита держит сегменты, склейку и итог
одновременно — на фильм в 1.4 ГБ ушло около 4 ГБ, и на стандартном разделе
ffmpeg падает с кодом 228, когда место кончается.

## Скачанное

Скачанная серия играет с диска, а не тянется с сервера заново. Смесь
скачанного и нескачанного получается сама собой: витрина одна, просто у
части серий есть локальный файл.

- Опись ведёт оболочка (`Library`): JSON в личной папке приложения, ключ —
  «тайтл:сезон:серия». Номера переживают переобход каталога, а числовой id
  серии может смениться. Сами файлы остаются в «Фильмы/kino» или в выбранной
  папке — в описи только адреса и состояние просмотра. Файл принадлежит
  человеку: если его унесли или стёрли мимо приложения, запись вычищается
  при следующем чтении описи.
- Витрина берёт опись через `kinoApp.library()` (модуль `native.ts`). На
  странице тайтла скачанные серии помечены, у текущей появляется «Смотреть
  скачанное»; раздел «Скачанное» в меню виден только в приложении.
- Играет `PlayActivity` на ExoPlayer. Отдельный экран нужен потому, что
  **WebView не открывает Matroska** (`canPlayType('video/x-matroska')` — пусто),
  а в нём лежат несколько озвучек и субтитры. Тема у экрана своя: заставочная
  построена на `Theme.SplashScreen`, а `AppCompatActivity` под ней падает.
- Прогресс пишется в опись, а не сразу на сервер: скачанное смотрят как раз
  без сети. Витрина отдаёт накопленное при первом заходе со связью
  (`syncLocalProgress`) и снимает пометку. В kinopub по-прежнему не пишем.
- Ничего не удаляется само. Просмотренное лежит отдельным списком, место
  освобождает человек.

### Без сети

Без сети витрина не грузится, а качают ровно ради этого случая. Поэтому в
APK лежит своя страница (`www/error.html`) — приложение без сети: тайтлы
плитками с постерами, внутри серии с кадрами, прогрессом и отметкой
«просмотрено», «Смотреть» / «Продолжить», стереть; «назад» и стрелки пульта
работают. `kinoApp` добавлен ко всему WebView, поэтому доступен и на ней.
Перерисовывается по возврату из плеера и по сигналу оболочки
(`kinoLibraryChanged`); перезагружать её нельзя — `https://localhost` для
Capacitor чужой адрес, и он отдаёт его браузеру.

- **Не ждём таймаутов.** Capacitor сам запрашивает страницу витрины с
  таймаутами по 30 с на соединение и чтение: на Wi-Fi без интернета человек
  минуту смотрел на заставку. `MainActivity` смотрит на сеть: её нет — сразу
  страница скачанного; есть, но без проверенного выхода в интернет — 5 с;
  обычная — 15 с до первого ответа.
- **Превью видны без сети** (`Previews`): кадр вынимается из самого файла
  (`MediaMetadataRetriever`, 15% длины, не дальше 2 мин), постер тайтла
  скачивается, пока сеть есть. Лежат в `files/art`, страницам отдаются по
  `/_kino/art/<имя>` — путь перехватывает `KinoWebViewClient`, у витрины и у
  страницы без сети одинаково.
- **Старые загрузки.** Всё скачанное до 6 сентября (до описи) в «Скачанное»
  не попадало вовсе. Теперь при запуске оболочка ищет видео в
  «Фильмы/kino/<название>/» (свои файлы MediaStore показывает без
  разрешений) и в выбранной папке и добавляет то, чего нет в описи. Номер
  тайтла у такого файла неизвестен — витрина находит его по названию папки
  подсказками (только наш каталог, kinopub не трогается), одноимённые не
  угадывает. Смотреть и стирать можно и без номера.

Без сети бывает и витрина, а не только эта страница:

- страница пришла, а API нет (связь оборвалась на полпути или лежит core) —
  вместо входа по коду экран «Нет связи» со списком скачанного
  (`pages/Offline.tsx`); вход показывается только на 401/403;
- связь пропала посреди работы — сверху полоска «Нет интернета» со ссылкой
  на «Скачанное», страница тайтла пишет «нет связи с сервером» и даёт
  запустить его скачанные серии.

«Смотреть» не передаёт позицию: при нуле `PlayActivity` берёт её из описи
сам, а список на странице мог устареть, пока играл родной плеер.
Досмотренное идёт с начала (1 мс — ноль занят под «с места в описи»).

Проверено на эмуляторе: загрузка → запись в описи → раздел «Скачанное» →
воспроизведение с диска → позиция сохранена → при возврате в сеть прогресс
уехал на сервер. И то же самое с выключенными Wi-Fi и передачей данных.

## Вход

В приложении вход по умолчанию — по коду: экран показывает QR со ссылкой
`/#/link/<код>` и тот же код словами, человек подтверждает с устройства, где
уже вошёл. Пароль на телефоне набирают вслепую по стеклу, и это единственное
место витрины, где приходится это делать; на телевизоре — тем более. Обычная
форма никуда не делась и открывается текстовой кнопкой внизу.

У нового человека подтверждать не с чего: он ещё нигде не вошёл. Его
заводят в админке («Пользователи» → «Новый пользователь», без инвайта), а
код с экрана его телефона вводят в карточке этого пользователя («Вход по
коду»): устройство входит как он. QR при этом своим телефоном не сканируют —
ссылка подтвердит вход в аккаунт того, кто сканировал. Там же, в карточке, —
перенос из kinopub: журнал просмотров за последние дни (с настоящими
датами — «История» и «Продолжить смотреть» встают по порядку), личная папка
закладок в «Буду смотреть» и, если нужно, весь общий «я смотрю» (у него дат
нет — всё получит сегодняшнюю). С главной витрины перенос убран: он тратит
общий аккаунт площадки.

Витрина понимает, что она в приложении, по тому же `window.kinoApp`
(`hasApp()` в `native.ts`), — как и везде. QR рисует свой кодировщик
(`components/Qr.tsx`), зависимости ради одной картинки не берём.

## Плеер: внешний, форточка, статистика

- **Внешний плеер.** «Внешний плеер» на странице тайтла и настройка «чем
  открывать» отдают видео системному выбору (`ExternalPlayer`). Списка
  приложений у нас нет намеренно — он устарел бы на следующем установленном
  плеере. Ссылка тикета авторизует сама, поэтому чужому плееру не нужна наша
  сессия; скачанное уходит как `content://`. Перед показом выбора спрашиваем
  `queryIntentActivities`: `createChooser` открывает окно даже когда открывать
  нечем. Для этого в манифесте объявлен `<queries>` — с Android 11 чужие
  пакеты иначе не видны. Внешний плеер не сообщает, докуда досмотрели, поэтому
  прогресс по скачанному сохраняет только встроенный.
- **«Картинка в картинке».** В WebView своего PiP нет:
  `document.pictureInPictureEnabled` там `false`, а запрос отклоняется молча,
  и кнопка выглядела рабочей. Теперь витрина зовёт `kinoApp.pip()`, а тот —
  `enterPictureInPictureMode`. Перед этим плеер разворачивается на весь экран:
  в форточку попадает всё окно приложения, иначе там оказалась бы шапка
  страницы. Кнопка не показывается, когда не работает ни браузерный PiP, ни
  оболочка.
- **Статистика потока** — полупрозрачной сводкой в углу кадра: кодек,
  разрешение, битрейт, оценка канала и буфер. Гаснет вместе с панелью.
  Движок отдаёт мгновенные показатели через необязательный `stats()`.
- **Настройки** (`#/settings`): чем открывать, показывать ли статистику,
  автозапуск следующей серии, режим телевизора. В приложении лежат у оболочки
  (`getSetting`/`setSetting`), потому что их должны одинаково видеть витрина,
  встроенный плеер и страница без сети; в браузере — `localStorage`.
