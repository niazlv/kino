# Вход устройства

Как утилита-загрузчик (или любой клиент без браузера) получает сессию
платформы и живёт с ней без браузерных куки. Схема — device authorization
grant (RFC 8628) в упрощённом виде: клиент один и заранее известен, поэтому
OAuth-клиентов и секретов нет.

## 1. Код

```
POST /api/v1/auth/device
{"device": "kinopub 0.8.0 on MacBook"}

200 {"deviceCode": "…", "userCode": "KJ7Q-3MTR",
     "verificationUrl": "https://kino.example/#/link/KJ7Q-3MTR",
     "expiresAt": "…", "interval": 5}
```

`deviceCode` — секрет устройства, им оно опрашивает; не показывать.
`userCode` и `verificationUrl` — человеку: QR со ссылкой и код текстом.
`device` — как устройство представится человеку и в админке; до 80 знаков.

## 2. Подтверждение

Человек открывает ссылку в браузере, где уже вошёл, видит имя устройства и
нажимает «Впустить» или «Не впускать». Без сессии страница сначала попросит
войти. Без камеры код вводится руками в профиле витрины (`…/#/profile`,
«Подключить устройство») — или на `…/#/link`. Устройство входит в аккаунт
того, кто подтвердил; администратор может подключить его к чужому аккаунту
из карточки пользователя в админке.

Подключённые устройства видны в профиле («Где вы вошли»), там же выход на
каждом из них:

```
GET    /api/v1/me/sessions              свои живые сессии витрины
DELETE /api/v1/me/sessions/{id}         выйти на одном устройстве (204; чужая — 404)
DELETE /api/v1/me/sessions              выйти везде, кроме этого ({"signedOut": n})
```

Вышедшее устройство не продлится и refresh-токеном.

## 3. Опрос

```
POST /api/v1/auth/device/token      не чаще interval
{"deviceCode": "…"}

200 {"token": "…", "refreshToken": "…", "expiresAt": "…", "refreshExpiresAt": "…"}
400 {"error": "authorization_pending" | "slow_down" | "access_denied"
             | "expired_token" | "invalid_grant"}
```

Подтверждённый код одноразовый: сессия выдана — код забыт.

## 4. Использование

`Cookie: kino_session=<token>` на всех запросах к платформе, как у браузера.
Сессия — обычная пользовательская: в админке она отмечена как «устройство»
и отзывается там же.

## 5. Продление

```
POST /api/v1/auth/refresh
{"refreshToken": "…"}

200 {"token", "refreshToken", "expiresAt", "refreshExpiresAt"}   новая пара
401 refresh неизвестен или уже обменян (ротация: прежняя сессия отозвана)
403 сессия отозвана или пользователь заблокирован
410 refresh истёк — только новый вход
```

Сроки: `token` 30 дней, `refreshToken` 180 дней и скользящий — каждое
продление выдаёт новый на тот же срок. Клиенту стоит продлевать заранее
(например, когда до истечения `token` меньше суток) и по ответу 401 на
обычный запрос. Оба токена — секреты: хранить как пароль.
